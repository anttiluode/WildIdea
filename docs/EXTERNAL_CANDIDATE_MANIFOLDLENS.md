# External candidate: ManifoldLens teacher-query scheduling

Date: 2026-08-14

This note records the strongest existing-repo candidate found after the W4b stop rule.
It is **not a result** and does not reopen the synthetic WildIdea ladder.

Candidate repo:

```text
anttiluode/ManifoldLens
```

## Why this one qualifies

The current `manifold_lens.py` already contains a real online teacher/student loop:

```text
live webcam frame
      |
      v
ChiralField2D motion / novelty statistics
      |
      v
teacher scheduler decides whether to query SDXL-Turbo
      |
      v
expensive teacher image
      |
      v
(frame, teacher target) enters persistent replay buffer
      |
      v
student U-Net keeps training from accumulated pairs
```

The teacher loop currently declares:

```text
need_bootstrap = len(buffer) < 24
pose_is_new    = mass_since_harvest > 2.5
slow_refresh   = seconds_since_harvest > 5.0
minimum gap    = 0.4 s
```

When those conditions request a harvest, the actual SDXL image-to-image pipeline runs and the resulting pair is pushed into the replay buffer. The student then samples that persistent buffer and updates its weights.

So this system contains features the closed W1-W4b toys did not genuinely have:

1. **real query cost** — SDXL inference consumes wall-clock/GPU compute;
2. **external state** — webcam/video frames are not generated by the benchmark;
3. **persistent consequences** — querying a frame changes the replay buffer and therefore later student weights;
4. **state-contingent value** — a teacher query on a genuinely new pose can plausibly be worth more than a redundant query during an unchanged pose;
5. **a boring compile/runtime adversary is obvious** — periodic/fixed teacher schedules can be selected offline from calibration video.

This is therefore a legitimate place to ask the WildIdea/Pivot question again.

## Why SmartFly is second, not first

`Smartfly` also has persistent internal state and a view cone whose orientation changes observations. It would be a natural active-looking experiment.

But in the software implementation, reading another image crop is nearly free. Any claimed query cost would have to be invented unless the sensor itself were physically constrained.

ManifoldLens already pays a real cost for the action under test: invoking the teacher.

## Proposed external gate

Do not run this on generated motion patterns.

Use real prerecorded video so every policy sees exactly the same external sequence and the run can be repeated.

### Phase A — build a teacher cache once

Freeze:

```text
SDXL model/version
prompt
strength
locked teacher seed
input resolution
video files
frame sampling rate
```

For each benchmark video, cache deterministic teacher targets for the union of frames that may be used as:

```text
candidate training queries
+
held-out evaluation frames
```

The expensive cache build is measurement acquisition, not policy scoring. Record actual teacher wall-clock time per target.

After the cache exists, all policies can be replayed repeatedly without querying SDXL again, while still charging each selected query its measured acquisition cost.

### Phase B — policy comparison

Start every policy from the exact same student initialization and replay/training RNG state.

At minimum compare:

```text
A. current ChiralField state-triggered scheduler
B. best periodic schedule compiled on calibration videos
C. best fixed-position-in-clip schedule compiled on calibration videos
D. uniform schedule matched to A's teacher-call count
E. random matched-count schedule (diagnostic only, not the strong baseline)
```

Do not let A choose more teacher queries for free. Compare either at matched call count or on a quality-vs-measured-teacher-cost Pareto frontier.

### Training semantics must be controlled

The live GUI currently lets teacher inference and student training contend for one GPU lock. That makes wall-clock scheduling itself change how many student updates fit between teacher calls.

For the scientific benchmark, make this explicit rather than accidental. Two acceptable views are:

```text
CONTROLLED COMPUTE VIEW
    fixed student-update budget per incoming frame/query
    teacher cost charged separately

REALTIME SYSTEM VIEW
    preserve the actual shared-GPU lock
    charge total wall-clock/GPU occupancy
```

If both are reported, even better. Do not silently mix them.

## Primary outcomes

Measure on teacher-labelled frames not used as training queries:

```text
student L1 to locked teacher target
LPIPS or another preregistered perceptual distance if available
identity/structure metric only if its obligations are checked first
teacher queries used
measured teacher wall-clock/GPU time
student updates / student wall-clock
```

The main plot should be quality versus real teacher cost, not quality alone.

## Strong compile baseline

The W4b lesson applies directly.

Use calibration videos to search periodic schedules and any small frozen schedule family before the holdout videos are touched.

Freeze the Pareto set.

Then score the Chiral scheduler and frozen compiled schedules once on disjoint holdout videos.

A positive runtime result requires the live-state scheduler to occupy a holdout Pareto point that the compiled schedules do not reach.

If a periodic/offline schedule matches it, close the runtime claim for this system too.

## Important attribution

Even a positive result would not show that the ChiralField mathematics is special.

A second runtime control should use a boring novelty signal, for example frame-difference / optical-flow magnitude with hysteresis.

The attribution ladder is:

```text
compiled schedule
    vs
runtime state-triggered querying
    vs
specific ChiralField trigger
```

Only credit the narrowest layer that survives its boring control.

## Relation to TWC / KYY / SOL

TWC:

```text
query only distinctions that survive declared nuisance
```

KYY:

```text
score consequences relative to the receiver/objective, not arbitrary hidden motion
```

SOL-07:

```text
compile the whole handoff when the environment permits it
```

ManifoldLens adds the missing runtime condition:

```text
new external frame arrives
    -> value of another expensive teacher query can change
    -> query changes persistent student state
```

That is exactly the boundary WildIdea was waiting for.

## Stop rule

Do not replace the real teacher with a toy convolutional teacher and call that the external result.
A cheap teacher may be used only for unit tests of the harness.

Do not use generated motion clips as the primary holdout.

Do not tune the Chiral thresholds on holdout clips.

If a strong offline/periodic schedule matches state-triggered teacher acquisition after charging real teacher cost, stop. The point is not to rescue adaptive querying; it is to find out whether this existing practical system genuinely needs it.
